# 读书蒸馏

当用户在对话中提到“读书蒸馏”时，调用本 Skill 的完整流程，把指定书籍蒸馏成结构化、可长期保存、可独立打开的单文件 HTML。

## 固定内容结构

1. Hero / 书籍视觉封面
2. 书籍信息（书籍档案）
3. 一句话总览
4. 全书章节脉络图
5. 章节摘要——快速浏览：这本书每章讲了什么？
6. 章节精读——深度吸收：这一章有什么关键表达，以及我能怎么用？
7. 3–6 条金句引用块
8. 全文对工作和决策的行动启发
9. 适合谁读
10. 页脚 / 来源说明

> 关键区分：章节摘要与章节精读不得合并。摘要强调覆盖全书、信息压缩和快速扫描；精读强调每章的核心表达、原文依据以及对工作和生活的具体启发。

## 调用规则

- “读书蒸馏” = 调用本 Skill。
- 用户提供书籍 PDF、文档、网页全文或其他可读资料后，先完整读取源材料，再按本 Skill 输出。
- 不凭记忆补齐原书没有的信息；无法从源材料确认的内容明确标注“待补充/待核对”。
- 扫描版 PDF 先 OCR，再继续完整阅读。
- 执行前先判断用户的核心目标；如果核心目标不是“理解、吸收和长期复用知识”，不要强行套用完整读书蒸馏结构。

## 任务路由

先判断“用户提供的材料 + 用户真正想完成的任务”。

| 用户核心目标 | 默认处理方式 |
|---|---|
| 理解一本书、长篇知识材料并长期复用 | **读书蒸馏** |
| 分析 Excel、CSV、数据库、统计数据、日志等 | 数据分析 / 数据处理 |
| 按步骤执行工作、理解 SOP、操作手册、API 文档 | 流程提炼 / 操作指南 / 技术文档解析 |
| 获取新闻、实时行情、最新政策、最新价格、最新产品信息 | 实时检索 / 研究 |
| 比较、评估、预测、风险判断或辅助做选择 | 研究分析 / 决策分析 |
| 短通知、邮件、聊天记录、短说明等 | 直接处理，不套用完整读书蒸馏 |

## 不适用边界

“读书蒸馏”适用于以**知识理解、吸收和长期复用**为主要目的的书籍及长篇内容。以下情况不应直接使用完整的标准读书蒸馏结构：

### 1. 数据分析类

包括 Excel、CSV、数据库、统计数据、日志、原始调查数据、数据报表等。

这些材料的核心任务通常是发现规律、计算指标、制作图表或得出数据结论，应进入数据分析或数据处理流程。

### 2. 操作与流程类

包括 SOP、操作手册、API 文档、产品说明书、安装指南、工作流程、制度文件、技术规范等。

这类材料的核心目标通常是“怎么做”，应优先进入流程提炼、操作指南或技术文档解析流程。

### 3. 实时信息类

包括新闻、实时行情、股票/汇率价格、房地产实时数据、最新政策、法律法规最新版本、产品最新价格、AI 模型最新能力、公司最新动态等。

这类内容必须关注时效性，应先进行实时检索和必要的多来源验证，不应仅依赖“读书蒸馏”。

### 4. 决策与评估类

如果用户的核心目标是比较、评估、预测、风险判断、方案选择或投资/采购等决策，不应只做读书蒸馏。

可以先提炼材料中的事实与观点，但最终任务应进入研究、比较或决策分析流程。

### 5. 短文本

通知、邮件、聊天记录、短文章、简单说明等，不需要强行套用 Hero、章节地图、章节精读等完整结构。

### 6. 原始资料不足

如果无法获得足够的原文内容，不得假设、补写或虚构章节、观点、金句和关键原文。

应明确标记“资料不足”“待补充”或“待核对”，必要时请求更完整的源材料。

### 7. 扫描 / OCR 质量不足

如果原始 PDF 无法可靠识别，特别是目录、章节标题或关键原文存在严重 OCR 错误，不得把推测内容伪装成原书结构。

应标记 OCR 风险，并在可能的情况下要求人工核对。

## 可兼容但需要切换模式的内容

以下材料可以使用“蒸馏”思想，但不强制使用标准书籍结构：

- **学术论文** → 论文精读模式
- **长篇文章** → 文章蒸馏模式
- **演讲稿** → 演讲蒸馏模式
- **课程材料** → 课程蒸馏模式
- **报告** → 报告蒸馏模式

切换模式时，应根据原始资料的组织方式调整结构，不得为了套用模板而虚构“章节”。

## 工作流

### Step 1 · 通读全书

PDF、Word、网页全文都必须完整阅读；扫描版 PDF 先 OCR 再完整阅读。同步记录作者、出版信息、领域、完整章→节目录、每节核心观点、关键概念、可引用原文及出处。

### Step 2 · 提炼内容

按 references/content-spec.md 固定结构组织。

- 所有事实、数字、章节/节名、引用必须由原书支持；缺失信息标注“待补充”，不凭记忆补齐。
- 章节摘要：每章覆盖全书结构；每节用 1–2 句写清“概念 + 书中要点”，用于快速扫描。
- 章节精读：每章固定三部分：①凝练摘要；②重点例句 / 关键原文；③对工作和生活的启发。它不是重复章节摘要，而是从“知道内容”推进到“理解表达并知道怎么用”。
- 重点例句 / 关键原文：短、准确、有章节出处；若无法确认逐字原文，不编造，标注“待核对原文”。
- 工作和生活启发：必须绑定本章具体概念，落到真实场景、行为或决策，不写泛泛鸡汤。
- 金句逐字摘自原书并标注出处；长段落优先转述。

### Step 3 · 准备素材

Hero 默认使用碧海蓝天、治愈感的大景图，无文字无人物；真实书籍封面使用可靠来源获取并核验。图片压缩后放到 assets/hero.jpg、assets/cover.jpg。

### Step 4 · 填充模板

复制 assets/template.html 到任务目录。保留区块 id：bookinfo / overview / map / chapters / chapter-deep / quotes / actions / audience。

章节摘要按每章复制摘要卡片；章节精读按每章复制精读卡片，固定为“凝练摘要 / 重点例句或关键原文 / 对工作和生活的启发”。

### Step 5 · 压缩图片 + 内嵌

python3 scripts/optimize_images.py <hero原图路径> [<封面原图路径>]
python3 scripts/embed_images.py <任务目录>/index.html

最终交付 _embed.html 单文件，不依赖 assets/。

### Step 6 · 自检

如果可用，运行 HTML skill 的 scripts/shot.py。重点检查 clippedText、horizontalOverflow、responsiveChartIssues、consoleErrors 均为 0，并确认手机 Hero 标题完整可见、章节精读导航可用。

### Step 7 · 交付

只交付最终自包含 .html，清理截图、分片文件和临时素材。

## 质量红线

- 不编造原书没有的观点、数字、概念。
- 章节与节名必须与原书目录一致。
- 章节摘要 ≠ 章节精读：两者必须同时存在且承担不同阅读任务。
- 章节精读每章必须同时出现三项：凝练摘要、重点例句/关键原文、工作和生活启发。
- Hero 与标题在手机端完整可见；页面无横向滚动；导航锚点真实存在。
- 单文件交付必须真正自包含，图片使用 Base64 内嵌。
- 遇到不适用边界时，不为了完成模板而强行蒸馏；应切换到更合适的任务类型或模式。
